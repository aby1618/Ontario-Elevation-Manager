# Changelog

## 1.2.4

- Removed use of Python `xml.etree.ElementTree` from VRT sanitization and validation.
- Replaced XML parsing with a narrow text-level scanner that only recognizes GDAL-generated `VRTRasterBand`, `SimpleSource`, and `ComplexSource` elements.
- Resolves QGIS Plugin Repository Bandit B405/B314 findings without adding an external Python dependency or security-scan suppression.
- Nested mask-band sources remain excluded from elevation LUT modification.
- No intended change to terrain sanitization, source downloads, caching, VRT lifecycle, DTM/DSM handling, or exports.
- Retains QGIS 3.44+ / QGIS 4.x compatibility.

## 1.2.3

- Replaced fragile source-NoData guessing with a deterministic VRT-level sanitizer.
- Every VRT source now uses a GDAL ComplexSource LUT that preserves the complete plausible elevation range exactly while mapping extreme Float32 sentinel values to the VRT NoData value (-9999).
- Handles positive and negative extreme sentinels even when both occur in the same source tile.
- Preserves intrinsic source NoData and source masks generated by GDAL.
- Added VRT-definition QA to verify the sanitizer is attached to every elevation source before commit.
- Recomputes safe post-sanitization raster statistics so QGIS does not stretch the display using stale Float32 sentinel minima.
- Automatically hides the tile-index layer after a successful terrain build so selected-tile highlighting does not obscure the finished raster. Tile selections are retained in memory.
- Original Ontario source rasters are never modified.
- Retains overlapping-acquisition separation, package-resolution recovery, QGIS 3.44+/QGIS 4.x compatibility, and prior security-scan fixes.

## 1.2.2

- Fixed false terrain-QA failures when tiles from one Ontario acquisition use different source NoData sentinel conventions.
- Source NoData is now tracked independently for every raster instead of requiring one global value across the VRT.
- The generated VRT uses per-source GDAL `ComplexSource/NODATA` rules so positive and negative Float32 sentinels can coexist safely in one acquisition while the output VRT continues to use `-9999`.
- Retains source preflight and VRT postflight QA; unexplained extreme values in an individual source still stop the build and identify only the affected tile.
- Terrain QA tooltips now report when multiple source NoData conventions were normalized.
- No source Ontario raster is modified.
- Retains overlapping-acquisition separation, package-resolution recovery, and QGIS 3.44+/QGIS 4.x compatibility.

## 1.2.1

- Fixed extreme Float32 source NoData sentinel contamination in newer Ontario TIF elevation products such as GTA 2023.
- Added source-raster QA before VRT creation.
- Detects implicit extreme source NoData values even when they are not exposed by GDAL as band NoData.
- Normalizes detected source NoData to the plugin VRT NoData value (`-9999`) using GDAL `srcNodata`.
- Added VRT postflight QA. A VRT containing an extreme floating-point sentinel is rejected before it can replace the existing terrain.
- Raster QA failures identify and highlight affected source tiles and leave the existing terrain unchanged.
- Successful builds expose QA information through the terrain status tooltip.
- The QA workflow applies to both DTM and DSM and to IMG/TIF/TIFF source products.
- Retains overlapping-acquisition separation from v1.2.0 and QGIS 3.44+/QGIS 4.x compatibility.

## 1.2.0

- Added automatic detection of overlapping Ontario LiDAR acquisition/source projects within an AOI.
- Added a source-dataset chooser before tile selection when multiple acquisitions overlap.
- Source chooser reports acquisition year/vintage, resolution, vertical datum, tile count, package count and raster format when available from Ontario metadata.
- The newest identifiable acquisition is preselected by default; users may select one or multiple source datasets.
- Added a Section 3 source-dataset selector so each selected acquisition can be reviewed and tile-selected independently.
- Added batch terrain creation: multiple selected source datasets produce separate VRTs and are never merged together.
- Added source-specific VRT naming in overlap areas for clear provenance.
- Deduplicated tile-index records within each source project before reporting tile counts.
- Added TIFF support to the DTM adapter for newer Ontario acquisitions such as GTA 2023, while retaining legacy IMG support.
- Retained the v1.1.1 package-resolution fallback/problem-tile workflow and QGIS 3.44+/QGIS 4.x compatibility.

## 1.1.1

- Fixed DTM package resolution for legacy GTA/Halton package records whose package-index `DownloadLink` is blank.
- Added fallback resolution against official Ontario product-package metadata and known Ontario GTA archive naming patterns.
- Added non-blocking package-resolution handling: unresolved package groups no longer have to abort the entire terrain build.
- Added red map highlighting for tiles belonging to unresolved package groups.
- Problem tiles are automatically deselected so unaffected selected tiles can continue.
- Added options to zoom to problem tiles, open the active Ontario GeoHub dataset page, or provide a direct Ontario ZIP URL for an unresolved package.
- Valid manually supplied package URLs restore the affected tiles to the selection and re-run the normal workflow.
- Retained QGIS 3.44+ / QGIS 4.x compatibility and prior security-scan fixes.
